Большие мировые координаты

Большие мировые координаты (LWC) обеспечивают поддержку типов данных с двойной точностью в Unreal Engine 5 (UE5), где во всех системах движка внедряются масштабные изменения для повышения точности вычислений с плавающей запятой. Эти системы включают архитектурную визуализацию, симуляцию, рендеринг (Niagara и код HLSL), а также проекты с масштабными мирами.

В Unreal Engine 4(UE4) 32-битные типы с плавающей запятой ограничивали размер игрового мира. LWC значительно увеличивает размер ваших проектов, предоставляя 64-битные двойные значения для основных типов данных. Эти нововведения позволят вам создавать огромные миры и значительно повысят точность размещения и ориентации объектов. Большие мировые координаты готовы к использованию в новых проектах UE5.

Обновление вашего проекта до Unreal Engine 5

При обновлении проекта с UE4 до UE5 мы рекомендуем обратиться к Руководству по миграции, так как в некоторых случаях точность вашей кодовой базы может снизиться. Это не так критично для проектов, в которых не используются большие мировые координаты. Однако для проектов, в которых планируется использовать тип double для увеличения масштаба миров, мы рекомендуем воспользоваться Руководством по преобразованию больших мировых координат.

Эксперименты с большими мирами

По умолчанию размер WORLD_MAX составляет 88 миллионов километров, а проверка границ мира остается включенной.

Если вы хотите использовать размер UE4 WORLD_MAX в 21 километр, вы можете задать глобальное значение UE_USE_UE4_WORLD_MAX в EngineDefines.h, а затем перекомпилировать движок.

Это значение может измениться в будущих выпусках Unreal Engine, а также могут возникнуть проблемы со стабильностью, которые будут постоянно устраняться в процессе разработки Unreal Engine 5.

Blueprints

В Blueprints числа с плавающей запятой теперь отображаются с соответствующим подтипом одинарной или двойной точности. Этот новый тип поддерживает паритет функций с типами float и double. Все существующие Blueprints и типы Blueprints (UMG, Control Rig, Animation Blueprints) были неявно преобразованы для использования любого из этих типов точности без необходимости вносить изменения в предыдущие работы.

Интерфейс исходного кода

Теперь исходный код может использовать типы float и double. Unreal Header Tool(UHT) интерпретирует любой доступный в Blueprint тип с плавающей запятой в коде как Blueprint Float с соответствующим подтипом одинарной (C++ float) или двойной (C++ double) точности, что позволяет автоматически преобразовывать значения Float любой точности, поступающие от любого узла Blueprint.

Использование спецификаторов свойств UFUNCTION для значений Float

Любой метод, помеченный спецификатором свойства UFUNCTION и содержащий значение типа float, может привести к неточностям, поскольку значение Blueprint Float приводится к типу float с меньшей точностью. Важно проверить все существующие свойства UFUNCTION. Это поможет определить, нужно ли изменить параметры или возвращаемые значения на тип double, чтобы избежать проблем с точностью в будущем. Переключать типы float и double можно в любое время и в любом направлении.

Рендеринг

В Unreal Engine есть различные координатные пространства и преобразования, которые описывают, как объект может существовать в мире. Мировое пространство(координаты вашего уровня / мира) и Локальное пространство(относительно конкретного объекта). Дополнительную информацию можно найти в документации по терминологии координатных пространств.

Каждый объект, который можно разместить в мире вашего проекта, имеет три координатные оси, ориентацию и точку отсчета. См. Преобразование объектов для получения дополнительной информации.

Шейдеры

В UE5 появились новые типы HLSL, которые можно найти в файле LargeWorldCoordinates.ush . Дополнительную информацию о том, как преобразовать код шейдера в UE5, см. в документации по рендерингу в UE5.

Niagara

В Niagara реализация отличается от основной. Чтобы повысить производительность при работе с эффектами частиц, данные хранятся в виде набора чисел с плавающей запятой, а не в виде чисел двойной точности. Достаточно большой мир делится на ячейки сетки. Первое число с плавающей запятой определяет систему Ниагара в этой ячейке, а второе — ячейку, в которой находится система.

Для хранения этой дополнительной информации предусмотрен новый тип данных Position для хранения векторов, на которые ссылаются частицы.Position. Дополнительную информацию можно найти в документе Крупные мировые координаты в Niagara.

Обзор Движка Нейронной сети

Узнайте, как использовать эту функцию бета-версию, но будьте осторожны при ее применении.

Neural Network Engine (NNE) предоставляет общий API для доступа к различным средам выполнения нейронных сетей (иногда их называют провайдерами выполнения) и для оценки нейронных сетей без необходимости писать код для конкретной среды выполнения. Unreal Engine включает в себя отдельные среды выполнения, которые можно добавить в проект, включив соответствующие плагины. Вы можете динамически выбирать оптимальную среду выполнения для создания и запуска нейронной сети из ресурса NNE в проекте в зависимости от модели и целевого оборудования. NNE предоставляет различные интерфейсы, которые реализуются в средах выполнения для различных сценариев использования. Для каждого из этих сценариев может потребоваться свой способ запуска нейронной сети. Эти интерфейсы определяют, где будет выполняться нейронная сеть: на центральном процессоре, на графическом процессоре или на графическом процессоре с синхронизацией по времени с рендерингом кадра. Такая реализация обеспечивает максимальный контроль над тем, как и где в вашем проекте будет выполняться модель нейронной сети. С помощью NNE можно выполнять логический вывод в режиме реального времени, дополняя игру искусственным интеллектом (ИИ), а также реализовывать функции на основе редактора, такие как работа с ресурсами, запросы и инструменты для художников. Вот основные элементы, из которых состоит NNE:

  • Интерфейсы — это доступные части плагинов среды выполнения NNE.

  • Плагины среды выполнения — это плагины, используемые для реализации одного или нескольких интерфейсов в вашем проекте.

  • Активы — это ресурсы модели нейронной сети, которые можно импортировать в Unreal Engine при включенной среде выполнения.

  • Модели — это данные, хранящиеся в ресурсах модели нейронной сети.

Интерфейсы

Интерфейсы — это доступные части подключаемого модуля среды выполнения NNE. Чтобы сделать API понятным и информативным, вместо прямого доступа к среде выполнения используется класс интерфейса, который реализует среда выполнения и предоставляет API для этой среды выполнения. Каждый интерфейс предназначен для одного четко определенного сценария использования, и среды выполнения реализуют интерфейсы в зависимости от того, способны ли они обрабатывать этот тип сценария. В качестве примера можно привести синхронный вызов логического вывода на центральном процессоре для синхронизации оценки модели с рендерингом кадра на графическом процессоре с помощью INNERuntimeCPU и INNERuntimeGPU. INNERuntimeRDG ставится в очередь асинхронно с помощью графа зависимостей рендеринга (FRDGBuilder). NNE предоставляет различные интерфейсы, каждый из которых предназначен для решения отдельной задачи, чтобы сделать API простым и понятным. Такая согласованность позволяет разработчикам среды выполнения сосредоточиться на поддержке соответствующих функций для каждого интерфейса. В будущем можно будет добавлять новые интерфейсы для новых сценариев использования, сохраняя при этом обратную совместимость. Доступны следующие интерфейсы:

Исполняемые среды

Исполняемые среды — это плагины, реализующие интерфейсы NNE. Исполняемые среды обычно регистрируются в NNE при запуске. Используйте функцию TArrayUE::NNE::GetAllRuntimeNames(), чтобы получить названия всех доступных исполняемых сред, независимо от того, какие интерфейсы они реализуют. Используйте шаблонную функцию TArrayUE::NNE::GetAllRuntimeNames(), чтобы получить предварительно отфильтрованный список имен сред выполнения, реализующих указанный интерфейс. Например, чтобы получить все среды выполнения, реализующие интерфейсы, которые работают на центральном процессоре, используйте UE::NNE::GetAllRuntimeNames(). Чтобы получить среду выполнения, используйте функцию TWeakInterfacePtrUE::NNE::GetRuntime(const FString& Name). Или получите соответствующую шаблонную функцию с помощью TWeakInterfacePtrUE::NNE::GetRuntime(const FString& Name).

Не все среды выполнения доступны на всех платформах, даже если соответствующий плагин включен. Если среда выполнения недоступна или доступна, но не реализует интерфейс, переданный в шаблонной функции, возвращаемый слабый указатель будет иметь значение null. Поскольку среды выполнения могут отключаться, перед использованием слабого указателя следует проверить его действительность. Среды выполнения обычно регистрируются, отменяют регистрацию, загружаются и выгружаются вместе с соответствующими плагинами и модулями. Однако время жизни и регистрации среды выполнения зависит от ее конкретной реализации.

Активы

Плагины NNE позволяют импортировать файлы моделей нейронных сетей непосредственно в Unreal Engine, если плагин Runtime поддерживает этот тип файлов. Unreal Engine создает активы NNE Model Data в браузере контента для импортированных моделей нейронных сетей.

Не все среды выполнения поддерживают все форматы файлов. Типы файлов могут отображаться как успешно импортированные, но создание соответствующей модели для конкретной среды выполнения может завершиться ошибкой. Ознакомьтесь со списком поддерживаемых средой выполнения форматов файлов.

При успешном импорте движок создает ресурс UNNEModelData. Откройте ресурс в браузере контента, чтобы включить или отключить модель для определенных реализаций среды выполнения в вашем проекте. Удаление ненужных реализаций среды выполнения повышает скорость упаковки и уменьшает размер пакета вашего проекта. По умолчанию каждая модель оптимизирована для каждой реализации среды выполнения, но рекомендуется выбирать только те реализации среды выполнения, которые вы планируете использовать. Unreal Engine загружает данные моделей NNE так же, как и другие ресурсы UE. Например, внутри объекта определяется общедоступная переменная класса типа UNNEModelData с декоратором UPROPERTY, и модель, назначенная ей в редакторе, загружается автоматически при создании объекта. Кроме того, для программной загрузки ресурса можно использовать функцию Unreal Engine LoadObject при условии, что известен путь к контенту.

Модели

Модель содержится в интерфейсе и реализуется средой выполнения с загруженным ресурсом UNNEModelData. Вы можете создать модель на основе этого ресурса с помощью следующих функций:

  • TSharedPtr INNERuntimeCPU::CreateModelCPU(const TObjectPtr ModelData)
  • TSharedPtr INNERuntimeGPU::CreateModelGPU(const TObjectPtr ModelData)
  • TSharedPtr INNERuntimeRDG::CreateModelRDG(const TObjectPtr ModelData)

Не каждая среда выполнения может создать модель на основе любого актива с данными модели NNE. Среды выполнения доступны в редакторе Unreal в качестве необходимого условия для создания моделей, но модель может не поддерживать вывод на текущей платформе. Вы можете использовать следующие функции, чтобы узнать, можно ли создать модель:

  • ECanCreateModelCPUStatus INNERuntimeCPU::CanCreateModelCPU(const TObjectPtr ModelData) const
  • ECanCreateModelGPUStatus INNERuntimeGPU::CanCreateModelGPU(const TObjectPtr ModelData) const
  • ECanCreateModelRDGStatus INNERuntimeRDG::CanCreateModelRDG(const TObjectPtr ModelData) const

Эти функции следует вызывать перед созданием модели. Даже если результат указывает на то, что модель можно создать, само создание может завершиться неудачей из-за внутренних ошибок. Перед использованием всегда проверяйте общий указатель на возвращаемую модель на предмет корректности.

Созданная модель обычно содержит неизменяемые буферы в качестве весов и параметров модели, которые являются общими для разных экземпляров модели. Вы можете освободить UNNEModelData после создания модели, поскольку модели внутренне сохраняют указатели на необходимые данные.

Экземпляры модели

Вы можете выполнить логический вывод, создав экземпляр модели на основе модели нейронной сети с помощью одной из следующих функций: TSharedPtr UE::NNE::IModelCPU::CreateModelInstanceCPU() TSharedPtr UE::NNE::IModelGPU::CreateModelInstanceGPU() TSharedPtr UE::NNE::IModelRDG::CreateModelInstanceRDG() Экземпляры модели обычно содержат данные, относящиеся к конкретному сеансу, в виде внутренних состояний и промежуточных буферов. Вы можете создать несколько экземпляров на основе одной модели, используя неизменяемые данные модели в качестве весов и параметров. После создания экземпляров модель можно удалить, поскольку экземпляры сохраняют собственные ссылки на все необходимые общие данные. Перед первым вызовом логического вывода необходимо вызвать следующую функцию, чтобы модель могла выделить внутренние буферы нужного размера:

UE::NNE::ESetInputTensorShapesStatus SetInputTensorShapes(TConstArrayView InInputShapes)

Среда выполнения сообщает о любых потенциальных ошибках, которые не удалось выявить при импорте или компиляции, и вам следует проверить возвращаемый код состояния. Функцию необходимо вызывать заново при каждом изменении формы входных данных. Избегайте ненужных повторных вызовов, чтобы снизить нагрузку на вычислительные ресурсы.

Вызывающая сторона владеет входной и выходной памятью любого экземпляра модели NNE. Вызывающая сторона должна следить за тем, чтобы память любого входного и выходного тензора оставалась в рабочем состоянии и не подвергалась изменениям на протяжении всего процесса логического вывода. Это требует особой осторожности при использовании многопоточных процессов.

Мы рекомендуем объединять входные данные в пакеты, так как эффективнее обрабатывать пакет целиком, чем выполнять несколько отдельных вызовов, если требуется оценить экземпляр модели несколько раз за тик или кадр. Если синхронизировать несколько вызовов с помощью пакетной обработки невозможно, несколько экземпляров могут выполнять логический вывод одновременно, не нарушая потокобезопасность, необходимую для NNE.

Минимальный пример NNE

Чтобы начать использовать нейронную сеть на центральном процессоре, вы можете воспользоваться приведенным ниже примером с необходимыми точками и фрагментами кода.

Для простоты и наглядности в этом примере не рассматриваются подробно способы подготовки и настройки входных и выходных тензоров. В этом примере также не проверяются результаты, что необходимо делать в реальных условиях. Дополнительную информацию о начале работы см. в кратком руководстве по Neural Network Engine.

Для начала:

  1. Включите плагин NNE Runtime в браузере Плагины в Unreal Engine.

  2. Добавьте модуль NNE в качестве зависимости в файл .Build.cs проекта.

  3. Импортируйте файл нейронной сети (например, файл типа *.onnx ) в Unreal Engine через браузер контента.

Загрузите и запустите модель с помощью следующего кода:

// Include the NNE headers #include “NNE.h” #include “NNERuntimeCPU.h” #include “NNEModelData.h” // Create the model from a neural network model data asset TObjectPtr ModelData = LoadObject(GetTransientPackage(), TEXT("/path/to/asset")); TWeakInterfacePtr Runtime = UE::NNE::GetRuntime(FString("NNERuntimeORTCpu")); TSharedPtr ModelInstance = Runtime->CreateModelCPU(ModelData)->CreateModelInstanceCPU(); // TODO: Setup input and output tensors and tensor bindings as well as corresponding input shapes // Prepare the model given a certain input size ModelInstance->SetInputTensorShapes(InputShapes); // Run the model passing caller owned CPU memory ModelInstance->RunSync(Inputs, Outputs);
